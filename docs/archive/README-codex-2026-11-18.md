# Java Mentor Bot

Личный Telegram-бот для подготовки к Java-бэкенд стажировке. Сам присылает задания и напоминания, пока сервис запущен. В двухчасовом уроке 45 минут занимает теория, 25 минут алгоритмы и 30 минут вопросы собеседования. Ещё 20 минут отведены на практику, например шаг по T04B с учётом дедлайна. T04B доступен как готовая карточка с последовательностью шагов. D01 фигурирует только в еженедельном вопросе о прогрессе.

## Запуск

1. Создай бота через [BotFather](https://core.telegram.org/bots/features#botfather) и напиши ему в личный чат. Узнай свой числовой Telegram ID. Его также можно посмотреть в поле `message.from.id` ответа [getUpdates](https://core.telegram.org/bots/api#getupdates), вызванного с токеном своего бота до запуска сервиса.
2. В этой папке сделай `cp .env.example .env`. Заполни `TELEGRAM_BOT_TOKEN` и `TELEGRAM_OWNER_ID` в локальном файле. Для теории укажи абсолютные пути к PDF в `MENTOR_PROJECT_PDF` и `MENTOR_SPRING_PDF`. SSH-адрес T04B можно указать в `MENTOR_T04B_SSH` или передать после дедлайна в команде `/t04b`.
3. Собери и запусти сервис. Для сборки нужен установленный JDK 21 и доступ к зависимостям при первом запуске. Для запуска JAR нужен Java 21 или новее.

```sh
./gradlew test bootJar
set -a
. ./.env
set +a
java -jar build/libs/java-mentor-bot.jar
```

Для быстрого старта база H2 сохраняется в `data/`. Для PostgreSQL укажи `MENTOR_DB_URL`, `MENTOR_DB_USER`, `MENTOR_DB_PASSWORD` и заранее создай базу. Запускай один экземпляр бота с одним токеном. Для уведомлений при выключенном компьютере запускай сервис на постоянно доступном хосте. Токены и ключ модели хранятся в настройках запуска.

## Проверка доставки

Когда сервис запущен с токеном, отправь боту `/start`. Для проверки уведомлений укажи сегодняшний день недели и начало двухчасового окна через 5–10 минут, затем подтверди `/week`. Бот пришлёт напоминание в пределах 15 минут до начала и отдельное сообщение при старте. После проверки выбери свои обычные окна. Подтверждённое окно можно один раз перенести командой `/move`.

Если через 30 минут с начала урока ещё нет зачтённого ответа или попытки на проверке, бот напомнит о первом шаге. После пропущенного окна он отдельно предложит начать следующее занятие с 10 минут. Сообщения о пропусках отправляются с 09:00 до 22:00 по часовому поясу расписания.

## Первый план

- `/start` покажет команды. Часовой пояс по умолчанию — Москва. Его можно поменять через `/zone` до первого подтверждённого плана.
- `/t04b ГГГГ-ММ-ДД` добавит крестики-нолики. Возьми точную дату из кабинета Школы 21.
- `/windows 1=19:00 2=19:00 3=19:00 4=19:00 5=19:00 6=12:00 7=12:00` задаёт пример свободных окон на неделю. Номера соответствуют дням с понедельника по воскресенье.
- `/week` покажет черновик на семь дней. Нажми **Подтвердить**, чтобы запустить напоминания. `/today` покажет текущий шаг. Чтобы сдать ответ, нажми **Ответить** или напиши «Вот моё решение: …». Команда `/submit` тоже работает, `/hint` даёт одну подсказку.
- В свободном режиме бот напоминает о незакрытых шагах в 10:00, 14:00, 18:00, 20:00, 21:30, 22:30 и 23:30 по твоему часовому поясу. Напоминание показывает реальный счёт из базы, долг и стрик (день в стрик — от двух зачтённых шагов). Бот пропускает напоминание, если урок зачтён, день поставлен на паузу или ответ на проверке. Каждое окно отправки длится час, поэтому после восстановления связи старые напоминания не придут пачкой.
- `/lesson` или `/lesson 1` показывает подготовленный урок до его начала. Для каждой ссылки есть конкретная тема, граница чтения и примерное время: 25 минут чтения и 20 минут задания. Карточки собираются из проверенного каталога и сохраняются вместе с планом без вызовов ИИ. Кнопка **Материалы** есть в напоминаниях. `/materials` дополнительно показывает сохранённые плейлисты; пока их содержание не разобрано, они не выдаются как обязательная теория.
- `/report` показывает выполненные уроки, пропуски, карьерный шаг и строгие окна. `/career` помогает выбрать шаг к стажировке. `/vacancy` разбирает присланный текст требований.

## ИИ

Пиши ментору обычным сообщением. Например, «Что у меня завтра?» или «Распиши урок #1 подробнее». Модель видит расписание, выполненные шаги и переписку за текущий день по твоему часовому поясу, включая сдачи и разборы. Если переписка длинная, в запрос попадает её свежая часть. После полуночи новый диалог начинается без вчерашних реплик, но зачёты, решённые задачи и отметки по навыкам остаются в базе. `/newchat` очищает переписку вручную и сохраняет прогресс.

Во время урока ответ можно писать обычным сообщением. Отдельный классификатор (LLM_ROUTER_MODELS) решает, ответ это или вопрос: ответ сразу уходит на проверку, и вердикт приходит через несколько секунд. Вопросы, болтовня и чужой код на разбор на зачёт не отправляются. Зачёт и счёт шагов пишет только приложение после проверки; фразы модели вроде «урок пройден» из ответа вырезаются. В одном сообщении можно сдать несколько шагов. Незакрытый урок свободного режима на следующий день остаётся долгом и идёт первым. Пропущенный день обнуляет стрик и включает строгие часы 19:00–21:00 для Mentor Focus. Раз в день в случайное время бот задаёт вопрос по пройденной теме.

Ментор отвечает с иронией, допускает мат в подколах и реакции на результат. Формулировки заданий, технические пояснения к ссылкам, код и критерии остаются точными и без шуток. По умолчанию он даёт ссылки с указанием нужных разделов; объясняет теорию коротко только по прямой просьбе. У диалога и проверок есть ограничения длины ответа.

Для проверки ответов и подсказок укажи `LLM_MODEL`, `LLM_BASE_URL` и при необходимости `LLM_API_KEY`. Модель с префиксом `groq:` (например `groq:openai/gpt-oss-120b`) идёт в Groq с ключом `GROQ_API_KEY`. `LLM_REVIEW_MODELS` и `LLM_ROUTER_MODELS` задают модели для проверки и распознавания сдачи; после них пробуется основная цепочка. В логе видно, какая модель ответила на каждый запрос. Поддерживается API Chat Completions, например [Ollama](https://docs.ollama.com/api/openai-compatibility) с уже загруженной локальной моделью или доступный тебе облачный провайдер. Для облачной модели сервис отправляет выбранному провайдеру текст диалога и учебные данные или текст попытки и сведения о задании. SSH-адрес и файлы репозиториев в запросы не входят.

При недоступном ИИ расписание и уведомления продолжают работать. Бот хранит попытку для повторной проверки. Можно использовать `/selfcheck` и записать, как ты подтвердил результат. Отчёт показывает самопроверку отдельно.

## Проверки Java-проекта

Бот выбирает до двух случайных моментов в разные дни каждой календарной недели, между 11:00 и 20:00 по часовому поясу расписания. Дни паузы и учебные окна (включая 15 минут до них) исключены. Если сервис был выключен, сообщение можно отправить позже в тот же день до 21:00, за пределами занятия. За предыдущие дни сообщения не догоняются. Выбранные моменты и история отчётов сохраняются в базе, перезапуск их не меняет.

Проверки относятся к активному T04B или проекту с Java/Spring в названии или описании. Закрытые проекты и D01/DevOps исключены. Чтобы добавить T04B: `/t04b ГГГГ-ММ-ДД` (SSH-адрес берётся из настроек). Повторная команда `/t04b ГГГГ-ММ-ДД` обновит дедлайн активного T04B и сохранит прогресс. Отсутствие проекта в `/projects` означает, что случайные проверки ещё не запланированы.

В день сообщения можно отвечать обычным текстом. Позже — ответом на сообщение бота или через `/progress текст`. Модель отличает отчёт от обычного вопроса по Java. Она сравнивает конкретный результат и проверку с предыдущим отчётом, планом и дедлайном, учитывает 20 минут дополнительной практики. При недостатке данных уточняет, при явном бездействии подкалывает с матом и предлагает следующий шаг, при достаточном результате отмечает его с иронией. Сводку Git можно запросить отдельно через кнопку «Проверить Git» в меню проекта. Отчёт о проекте не засчитывает учебные задания: для этого нужно сдать работу. В `/report` отображается последний статус проверки.

Само случайное сообщение не вызывает модель. Один разбор ответа использует один запрос к ИИ. При сбое модели проверка остаётся открытой: повтори ответ через `/progress`. Ни D01, ни основной план подготовки к собеседованию проектные проверки не заменяют.

## Android

При двух пропущенных учебных днях за семь дней бот отмечает три ближайших урока как строгие. Ещё один пропущенный строгий день добавляет два окна. Через `/report` можно увидеть время от 15 минут до начала и до конца урока. Для блокировки выбранных приложений на эти интервалы настрой [режим фокусировки Android](https://support.google.com/android/answer/9346420?hl=en#zippy=%2Cpause-distracting-apps-temporarily). Для ограничений по экспортированным окнам доступен прототип Mentor Focus ниже. Активность в Telegram определяется по действиям в чате бота. Открытие Telegram через Bot API не видно.


### Меню и расширения

- Открой `/menu` в Telegram. Кнопки ведут к уроку, плану, проекту, отчёту, собеседованию и настройкам. В активном уроке кнопка «Ответить на задание» открывает поле ответа. В настройках «Свободные окна» открывает поле для шаблона недели.
- «Покажи материалы на завтра» открывает подтверждённый урок. «Я закончил раздел про интерфейсы и абстрактные классы» записывает отметку для следующих планов. «Запиши результат по проекту: …» сохраняет прогресс T04B или отправляет ответ на открытую проверку.
- Новые планы учитывают пробелы, срок повторения и отмеченные знакомые темы. `/topics` показывает идентификаторы. `/video ID ссылка | что посмотреть` добавляет конкретный ролик или ссылку с таймкодом к теме.
- `MENTOR_T04B_LOCAL_REPO` задаёт локальную рабочую копию. «Проверить Git» показывает последние коммиты, состояние рабочей копии и изменения с последней проверки. Настроенной модели передаются только метаданные Git и условие.
- «Собеседование» даёт пять вопросов по одному и сохраняет оценки навыков. Для голосовых укажи в `MENTOR_TRANSCRIPTION_MODEL` модель, поддерживающую Ogg на endpoint `/audio/transcriptions` того же провайдера. Аудио отправляется провайдеру только при включённой настройке. Пока настройка пуста, интервью принимает текст.

### Mentor Focus для Android

1. Собери APK командой `ANDROID_JAR=/path/to/android.jar ANDROID_BUILD_TOOLS=/path/to/build-tools ./android/build-apk.sh` и установи `build/android/mentor-focus.apk`.
2. В боте открой «Настройки → Окна для Android» и сохрани файл. Импортируй его в приложение. После переносов и изменений строгих окон повтори импорт.
3. Выбери отвлекающие приложения, включи сервис Mentor Focus в специальных возможностях Android и включи ограничения в приложении. В строгие окна сервис возвращает на главный экран при открытии выбранных приложений. Приложение показывает таймер и число таких возвратов. Данные приложения остаются на телефоне.

### Профиль памяти для Linux

Тестовый профиль JVM для отдельной службы:

```sh
java -Xms16m -Xmx80m -Xss512k -XX:+UseSerialGC -XX:ActiveProcessorCount=1 \
  -XX:TieredStopAtLevel=1 -XX:ReservedCodeCacheSize=24m -jar build/libs/java-mentor-bot.jar
```

При совместном размещении сначала замерь `MemAvailable`, своп и давление памяти во время нагрузки других служб. Для отдельной службы бота можно задать `MemoryHigh=150M`, `MemoryMax=192M` и повышенный `OOMScoreAdjust`, чтобы при дефиците памяти первым остановился бот. Стартовый замер профиля с пустой тестовой базой не заменяет измерение под рабочей нагрузкой.

На VPS защиту задают файлы в `deploy/systemd`. Установи скрипт в `/usr/local/sbin/mentor-memory-guard`, таймер и его службу в `/etc/systemd/system/`, а `50-memory-guard.conf` в `/etc/systemd/system/java-mentor-bot.service.d/`. После `systemctl daemon-reload` запуск службы `java-mentor-bot` поднимет таймер через `Wants=`.

Защита проверяет `MemAvailable` примерно каждые 5 секунд. Ниже 192 МиБ она останавливает бота, выдерживает минимум 300 секунд и ждёт 320 МиБ доступной памяти. Если бот исчерпает собственный лимит в 192 МиБ, systemd также отложит перезапуск на 300 секунд и проверит доступную память перед стартом. Своп для бота ограничен нулём. Посмотреть срабатывания можно через `journalctl -u mentor-memory-guard -u java-mentor-bot`.

Сообщения, присланные во время паузы, бот забирает из очереди Telegram после старта. Telegram хранит необработанные обновления до 24 часов. Позиция очереди и ответ на уже сохранённую команду хранятся в базе. При переносе службы используй одну рабочую копию бота с этим токеном и сохрани её базу.
